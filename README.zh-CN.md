# FitTrack · 轻衡 使用与开发指南

[返回项目主页](README.md) · [下载 Windows 便携版](https://github.com/LinZzzzJ/FitTrack/releases/latest)

## 便携版首次使用

1. 完整解压 ZIP 到固定且可写的程序目录，保留 FitTrack.exe 与 _internal。
2. 双击 FitTrack.exe，选择一个专用空文件夹作为数据根目录 R；已有有效根目录也可继续使用。
3. 在自动打开的本机页面注册账号。首个账号为本机管理员，没有默认密码。
4. 填写身高、初始体重、性别和设备静息能量；体脂与目标可选。
5. 如需 AI，在个人设置填写自己的 Key。以后使用程序目录生成的启动、停止、重启快捷方式。

默认地址为 http://127.0.0.1:8788。关闭网页后后台继续运行，使用停止入口退出；不创建开机启动项。端口冲突或原数据目录不可用时明确提示，不自动换目录或另开实例。

包内另有先读我.txt和离线首次使用指南.html。Windows 11 x64已验收；Windows 10为兼容目标，尚未实机验证。主EXE未签名，可用发布页的SHA-256核对文件。

> **当前源码与便携包：**下文标记为“当前 `main` 源码”的新增体验尚未进入 v0.4.0 便携包。公开仓库的应用版本仍为 v0.4.0，当前源码 API 修订号为 5；Windows 源码和浏览器检查已通过，新便携包尚未构建验收。

## 数据位置

程序与数据可以分开保存。数据根目录由你首次选择，没有隐式默认运行目录：

```text
R/
├─ fittrack-root.json   根目录标识
├─ control/            账号、会话、个人目录映射和加密AI凭据
├─ secrets/            主加密密钥
├─ records/<用户ID>/    个人数据库、原图和缩略图
├─ logs/               脱敏日志
├─ tmp/                暂存文件
├─ caches/             可重建缓存
├─ backups/<用户ID>/    个人健康备份
└─ runtime/            实例状态和管理任务
```

个人设置列出位置与占用空间。个人健康工作区可迁移到根目录内的专用子目录，不能选择其他账号或控制、密钥等保留目录。迁移采用复制、核验、切换并保留旧档。

应用临时目录固定R/tmp，运行时不写Python字节码缓存。程序目录会写绑定数据目录的快捷方式；浏览器Cookie、缓存及操作系统自身记录由它们分别管理。

## 个人AI配置

服务地址默认 https://api.deepseek.com，识图和文字模型默认 deepseek-flash。新账号的API Key为空，请到AI提供方申请自己的Key，并按账户实际额度使用。

Key使用密码框，保存后不回显；勾选记住时使用Fernet加密保存到控制库，主密钥独立保存。不勾选时仅在当前登录会话的后端内存保留，退出、过期或服务重启后需重新输入。Key由本机后端保管和调用，不属于仅保存在浏览器的方案。

连接测试检查鉴权，生成才提交相应照片或记录摘要。模型支持、计费、速度和可用性由提供方决定。无网络或Key时，手动记录、热量计算及图表仍可使用。

## 身体、饮食与历史补录

顶部日期决定新增记录的入账日期，支持昨天及更早日期。身体参数有生效日期，修改设置不会无故重写此前参数。

饮食支持拖入 JPEG、PNG、WebP 或 GIF 照片，单张最大 12 MB。填写实际吃下的部分，例如“鸡蛋只吃蛋白”。AI 草稿可改名称、重量和营养，确认后才入账；新增一餐与同日其他餐食累加。

原图保留上传字节，预览完整显示。发送AI的副本会修正方向并按需要等比缩小，不裁边。照片无法准确测量份量和烹调用油，结果需要人工核对。

包装食品请选择营养标签方式，核对每 100 克/每份/整包的基准和 kJ/kcal，再填写实际克数或每袋重量 × 袋数。未知字段留空，必要字段补齐后才可确认。示例：374 kJ/100 g，吃 60 g 约 53.63 kcal，吃 120 g 约 107.27 kcal。

**当前 `main` 源码：**手动录餐可选择两种模式。AI 估算输入餐食描述、可选附加照片，由 AI 拆分食物并生成可编辑草稿；精确录入填写整餐描述和蛋白质、碳水、脂肪总量，由后端按 `4/4/9 kcal/g` 计算热量。从 AI 草稿切换到精确录入时，三大营养素输入会清空，需要重新填写；已有精确记录的编辑值会保留。重量、纤维、总糖和钠可留空；两种模式都在确认后才入账。

饮食按 2026-10-15 起每七天分组，可翻看历史周，记录不会按周清除；更早日期也能查看和补录。餐食 AI 分析列表的删除按钮仅删除已结束的分析任务，确认后执行，已入账餐食和原图保留。删除餐食使用餐食卡片自己的入口。

## 训练、目标与AI建议

力量训练逐组记录总外加重量和次数。有氧记录类型、强度和时长，支持羽毛球；可根据备注调用 AI 估算整段平均 MET。预览不入账，采用后仍需保存训练。计划只有转为实际训练才计入消耗。

**当前 `main` 源码：**训练日历用标记显示存在实际训练记录的日期，排期状态另行显示。训练页提供背、胸、手臂、肩、腿等部位预置模板，也可保存个人模板；套用后当天编辑不会修改原模板。训练计划可通过列映射导入通用 CSV，或导入 FitTrack JSON；不会自动转换为已完成训练。个人模板可导出 JSON，也可用单模板离线二维码导入/导出。二维码容量有限，较大的模板请使用 JSON；摄像头扫码要求 HTTPS 或 localhost，也可上传二维码图片。

填写目标体重后可生成每日热量与三大营养素建议，预览、采用并保存。AI 不会自动修改目标或排期。当前 v0.4.0 便携版的目标建议仍为三大营养素；纤维、总糖和钠记录能力属于当前 `main` 后续源码，不会自动生成个体摄入目标。

首页每日反馈手动生成，也可只完成当日记录。每周复盘需周期结束，连续七天每天至少有一条已确认餐食并完成记录；没有训练的日期作为休息日，不要求每天称重。首期10/15—10/21在10/22解锁，记录变化后旧建议标记过期。

首页、身体与趋势图表起点统一为 2026-10-15，终点跟随所选日期。缺失体脂和测量不补零，七日均值按已有测量计算。

## 计算口径

```text
运动总消耗 = MET × 当天有效体重 × 分钟 / 60
运动净消耗 = max(0, 运动总消耗 − 静息能量 × 分钟 / 1440)
估计每日消耗 = 静息能量 × 日常活动系数 + 各次运动净消耗
估计热量缺口 = 估计每日消耗 − 已确认饮食摄入
```

**当前 `main` 源码：**未提供手动或设备静息值时，可用 Mifflin–St Jeor 公式估算：男性为 `10 × 体重 (kg) + 6.25 × 身高 (cm) − 5 × 年龄 + 5`，女性将常数项改为 `−161`；选择“其他”时采用两个常数项的均值。日常活动状态提供久坐、轻度、中度、高度和非常活跃五档；历史自定义活动系数仍兼容。估算不等同实测，也不是医疗建议。

力量训练量按重量×次数累计，自重动作另统计。食物热量按明细加总；蛋白质、碳水和脂肪按 4/4/9 kcal 每克计算供能比例。膳食纤维、总糖和钠单独汇总，若有食品未提供对应值，当日合计显示为空而不是零。运动和热量缺口均为估计，不能代替实际代谢测量。

## 备份、升级与换电脑

- 设置中手动创建健康ZIP备份，保存在R/backups内，不自动下载到其他目录。日常写入记录不等于独立备份。
- 当前 `main` 源码创建健康 ZIP v2，包含记录、照片和个人训练模板；仍可导入没有模板表的 v1 备份。备份不包含密码、API Key 或主密钥。换电脑可重新注册并导入，重新配置自己的 Key。
- 完整保留账号及凭据时，先正常停服，再复制整个R，包含secrets。不能只复制运行中的SQLite主文件而遗漏WAL。
- 恢复先验证到新工作区再切换，保留当前工作区。整根迁移由本机管理员通过设置操作。
- 升级前停止旧版并备份，把新版解压到新程序目录，运行新EXE选择原R，重新生成快捷方式。
- 主密钥丢失时健康记录仍可访问，已有Key密文无法解密；恢复完整备份或重新填写Key。

## 源码开发与检查

推荐Windows、Python3.12、Node.js24与Git。克隆后在PowerShell运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -ExecutionPolicy Bypass -File scripts/check.ps1
```

安装脚本建立项目虚拟环境、安装锁定依赖、构建前端并生成首次设置入口；检查脚本运行pytest、Ruff、Svelte检查和生产构建。测试数据和缓存位于artifacts，自动AI验证使用模拟接口，不读取正式Key。

便携版构建使用独立官方CPython3.13.16与PyInstaller6.22.3。prepare_release.ps1准备构建环境，build_release.py生成ZIP，check_portable_release.py和check_portable_ui.py验证成品，audit_release.py检查清单和校验。运行这些工具需按参数明确指定构建、输出或测试位置。

问题反馈请附版本、操作步骤和脱敏错误信息，不要在Issue中上传Key、个人数据库或完整日志。

## 工程目录与配置入口

```text
FitTrack/
├─ src/fittrack/         FastAPI、存储、计算、AI、任务及平台运行代码
├─ web/src/             Svelte 页面、组件、共用类型和状态
├─ tests/               自动测试，默认模拟 AI
├─ scripts/             安装、检查、构建和成品验收工具
├─ tools/               Windows 便携入口、PyInstaller 配置与 hook
├─ release-docs/        成品 TXT 与离线 HTML 指南
├─ docs/                架构、验收及项目知识库
├─ .github/workflows/   当前 Windows 自动检查
├─ AGENTS.md            AI 开发约定和阅读入口
├─ pyproject.toml       项目元数据、依赖要求、命令和检查配置
├─ requirements*.lock   开发、运行及构建依赖锁
└─ web/package-lock.json 前端依赖锁
```

`.venv`、`web/node_modules`、`src/fittrack/static` 和 `artifacts` 是本机依赖或生成产物，不随源码仓库迁移。前端生产构建输出到后端 static 目录。首次选择的运行数据根目录 R 与源码工程分开管理。

`src/fittrack/__main__.py` 调用 `cli.main`，先验证 R，再创建控制库、个人凭据和服务。生产配置在当前账号设置页输入；旧 `.env.example`/`config.Settings` 保留旧版导入和回归用途，不是当前所有账号共享凭据的入口。模型字段和管理命令参数以源码与 [接口说明](docs/interfaces.md) 为准。

主要输入为身体资料、明确日期的测量、食物/标签/份量、照片与补充描述、训练及个人 AI 配置；输出为持久记录、后端计算的热量收支与趋势、可确认 AI 草稿/报告，以及用户主动创建的健康 ZIP。

## Git、main 与 Release

公开仓库的 `main` 保存持续更新的源码，`v0.4.0` 标签标记已定版源码，GitHub Release 提供对应成品。当前版本文件和唯一版本标签仍为 v0.4.0；API 修订号 5 与上述新增源码功能尚无对应的便携包发布。想直接使用已验收版本，请下载 `FitTrack-v0.4.0-windows-x64.zip`；GitHub 自动提供的 Source code ZIP 是开发资料，不包含便携运行环境。

维护者曾在原工程的 `artifacts/github-public` 建立独立公开副本，保留原研发仓库和私人历史。这个外层目录不属于公开项目结构，其他人直接克隆即可。修改/提交/推送源码、重启运行实例和重新构建 Release 是不同动作，推送不会自动升级本机软件。
