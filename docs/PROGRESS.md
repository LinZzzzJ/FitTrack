# 版本进展

当前源码的应用版本字段仍为 v0.4.0；后续功能的 API 修订号为 5，但尚无新版 Release。此节只描述已发布 v0.4.0。

公开源码以一次干净的初始提交建立，不包含个人开发历史和运行数据。提供米白与深绿视觉风格的项目主页、模拟数据截图、中文使用说明和Windows便携包。

## 当前 main 源码 · 后续身体、饮食与训练功能

当前源码/API 修订号 5 增加静息消耗估算与活动等级、文字/可选照片餐食 AI 草稿、精确餐食三大营养素 4/4/9 热量计算、膳食纤维/总糖/钠、部位训练模板、CSV/JSON 计划导入、单模板离线二维码和实际训练日期标记。健康 ZIP 新建为 v2，兼容导入 v1；Meal 新增的模式与描述字段均可选，既有归档继续兼容。2026-10-23 精确录入确认规则再次细化：后端以宏量营养素覆盖客户端热量，并要求整餐描述及单项汇总。

最近一次已记录的 Linux Python 3.14 隔离测试排除 Windows 专属 `test_portable.py` 后 131 项通过、2 项跳过，Ruff、Svelte 检查及前端生产构建通过；完整 Linux 测试另有 Windows 启动器/注册表测试因系统 API 不存在而失败。本轮 Windows checkout 的 `scripts/check.ps1` 通过（142 项 pytest、Ruff、Svelte 检查及构建），Edge 隔离浏览器流程也通过。本轮未复跑 Linux 检查：WSL 缺少 `ensurepip`，无法创建项目 venv。新便携包尚未构建/验收；上述功能不能视为已包含在 v0.4.0 成品中。

精确录入重新进入时会清空三大营养素输入，避免沿用上一次精确草稿；Edge 回归验证重填后仍按 4/4/9 计算并确认入账。

便携版无需Python、Node或Anaconda安装，使用Windows原生目录选择和无控制台EXE。依赖、前端与必要运行库完整包含，首次选择数据根目录后生成启动、停止、重启快捷方式。

自动检查为129项后端测试、Ruff及前端检查/构建；成品与浏览器检查均使用独立测试数据和模拟AI。具体结果和限制见[公开验收记录](ACCEPTANCE.md)。
