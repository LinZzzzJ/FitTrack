# 网页部署技术评估

FitTrack共用 Svelte/TypeScript 前端和 FastAPI/Python 后端，前端构建由后端提供，浏览器通过同源 `/api` 访问。已发布交付为 v0.4.0 Windows 本机便携版（API 修订号 2）；当前 `main` 源码 API 修订号为 5，包含后续训练与饮食能力。服务器模式仍未完成公网部署验收。

## 两种运行方式

| 项目 | 本机版 | 服务器版路线 |
|---|---|---|
| 进程位置 | 用户自己的电脑 | 管理员维护的常驻服务器 |
| 入口 | 本机HTTP地址 | 域名与HTTPS |
| 数据位置 | 用户首次选择的根目录 | 管理员指定的服务器持久目录 |
| 个人健康空间 | 根目录内个人工作区 | 服务器分配的独立空间 |
| Key调用 | 本机后端 | 服务器后端 |
| 跨设备 | 通过备份导入 | 多设备登录同一服务器账号 |
| 文件夹/停止入口 | 允许相应本机操作 | 普通网页用户禁用 |

两种模式都由后端保管Key。服务器部署需信任服务器环境和管理员，不能宣称Key仅保存在浏览器。AI照片或相应记录摘要会交给所配置的AI服务。

## 已有接口基础

源码包含 local/server 能力开关、Host/Origin 检查、HTTPS Secure Cookie、可信代理参数、AI 提供方 HTTPS 允许列表、账号与个人凭据隔离，以及服务器禁用本机文件系统和进程管理能力的测试。当前 API 5 源码的训练模板、计划文件导入和餐食 AI/精确录入模式可由同源网页调用；它们尚未包含在 v0.4.0 便携包验收中。

训练模板二维码可上传图片解码；摄像头扫码依赖安全上下文，部署时使用 HTTPS（localhost 开发除外）并由用户明确授权摄像头。拒绝权限或无摄像头时，仍可用图片扫码和 JSON 文件交换。

当前使用单个应用进程，AI线程池全局并发上限为2，任务持久化到个人SQLite，SSE推送进度。不能直接通过增加Uvicorn worker获得正确的多进程队列行为；扩大规模需共享数据库、外部队列及协调机制。

## 真正开放公网还需完成

配置服务器与域名、HTTPS反向代理、上传和SSE超时、进程管理、持久磁盘、备份与恢复演练、升级回滚及故障监测。明确注册策略、登录限速、密码找回和每账号存储/AI任务额度，并在真实域名下验收登录、上传、任务、断线和重启。

服务器模式启动前须安全初始化管理员账号。部署管理员指定数据根目录；普通用户不能任意选择服务器磁盘路径。当前没有生产部署配方或真实公网服务可直接启用。

SQLite初期适用于单机部署，数据库应位于同机持久磁盘。较大规模再评估PostgreSQL、独立任务队列和对象存储。健康ZIP可用于导入服务器账号；完整保留账号和凭据则需要停服后迁移整个受控根目录。

## 纯浏览器方案对照

类似BrushGraft的纯浏览器方式可通过静态站点运行，数据由浏览器IndexedDB管理，AI直连依赖提供方CORS。它与当前后端模式在集中账号、跨设备同步、任意本机目录、关闭页面后的任务行为上不同，需要额外业务改造。

FitTrack保留后端，以复用现有存储、计算、AI校验及任务系统。本机与未来服务器模式的主要区别是后端运行位置及管理权限。

参考：[FastAPI部署概念](https://fastapi.tiangolo.com/deployment/concepts/) · [SQLite WAL](https://www.sqlite.org/wal.html) · [BrushGraft](https://github.com/zeroherolin/brushgraft)。

## Android 客户端适配

当前源码另包含 Android 配对、设备会话、增量同步和冲突保留。PC 浏览器继续通过同源 Cookie 访问，
Android 使用 HTTPS 与设备 Bearer 令牌。反向代理应原样转发 Authorization 和 `/api/mobile/*`，
不自行增加通配符 CORS；手机 native HTTPS 客户端不依赖浏览器 Cookie。
后台保持单进程与同机 SQLite；不得直接增加多 worker 运行共享队列。

服务器默认关闭新账号注册，登录和配对已有应用级限流。需要开放注册时由部署者显式传入
`--allow-registration`，并配置账号配额。正式开放公网前仍需认证网关或补充代理限流，
限制上传体积、配置可信代理地址、备份和演练回滚。配对限流、账号归属、ZIP 校验和 TLS 校验
已有源码测试，不等于公网部署或渗透测试验收。详见 [Android 指南](android.md)。
