# Android 与 PC 兼容

本轮 Android 源码基于 v0.4.0/API 5。Android 首包 applicationId 为
`com.fittrack.qingheng`，versionCode=40000，minSdk=26、targetSdk=35。
需要保持 Android System WebView 更新（前端构建目标为现代 WebView/Chrome）。
它复用 FitTrack Svelte 界面和配色；PC 的 FastAPI/SQLite、Cookie 登录和健康 ZIP
格式继续保留。新增移动同步使用独立 `protocol=1`，没有为增加可选接口而破坏性提升 PC API 修订号。

## 使用与数据位置

首次启动选择“仅在本机使用”或输入自己的 HTTPS 服务器地址与 PC 设置生成的配对码。
本机模式不需要电脑或账号服务器。AI 仍需联网与用户自己的 Key，手动录入、统计和动画可离线使用。
Android 系统沙箱是移动版受控根目录；SQLite/SQLCipher 保存健康记录、待同步操作和元数据，
原图按内容哈希存入应用私有目录。数据库密钥、配对令牌和个人 Key 由 Android Keystore 加密保护。
系统云备份关闭，用户使用健康 ZIP 主动备份；卸载会删除应用私有数据，卸载前先导出。

服务器需运行包含移动协议的新源码；旧 v0.4.0 Windows 附件可用健康 ZIP 交换数据，不能直接当作移动同步服务器。
服务器模式保留该账号的本机副本。启动、回到前台、联网和前台每 30 秒触发同步。
退出、撤销设备或切换账号不会删除原账号空间；重新配对同一服务器、同一账号可继续同步。
后台操作固定在发起时的账号、目录和服务器，切换模式不会把结果写入新账号。
后台被 Android 结束时，不承诺持续同步或 AI 任务继续执行；再次启动将本地未完成任务标为中断，
不会重发付费请求。Android 不提供 Windows 的“打开磁盘目录、停止 PC 服务、迁移根目录”入口，
对应的数据管理使用系统文件选择与分享界面。

## PC 双向交换

PC 设置 → 创建个人健康备份 → 将 ZIP 传到手机 → 手机设置 → 导入 PC 健康 ZIP。
反向使用手机“导出健康 ZIP”，再在 PC 设置导入。支持旧 v1 和当前 v2，包含资料、测量、
饮食、照片、任务、反馈、训练、排期、完成标记和个人模板。导入前显示记录数量并二次确认；
原档案留在加密数据库中，可从历史档案再次导出。原图不重编码，保留字节及 SHA-256。

健康 ZIP 不包含账号密码、AI Key、设备令牌、同步游标和冲突副本。跨账号导入会重新归属当前账号，
Key 需要重新配置。本机空间与服务器空间不会擅自合并；希望迁移时显式导出、导入。
桌面目录不能与手机直接共享 SQLite/WAL 文件。数据交换使用 ZIP 或同步接口。

## 动作与兼容

背、胸、肩、手臂、腿、核心、全身、有氧各 6 个动作，共 48 个。每个动作有原创 SVG
关节动画示意、设备/负重标记和暂停入口；只播放可见卡片，尊重减少动态效果偏好。
这是简化动作范围示意，并非医学或专业动作校正。没有复制 openGym 的受限 Gym visual 媒体。
目录以稳定 ID 管理，健康记录仍保存原有动作名称和组数结构，旧 PC 导入器不必理解媒体字段。
后续可在许可核实后增加位图/视频，不能把任意远程媒体 URL 当作可信应用资源。

## 同步与安全

PC 登录账号在设置生成 8 位一次性配对码，5 分钟有效，新码替代旧码。
兑换有每地址/全局频率限制。服务器默认关闭注册，并为登录添加限流；
部署者需新增账号时可显式使用 `--allow-registration`，本机注册流程保持原样。设备会话可在 PC 设置撤销，使用约 7 天后轮换，最长闲置 14 天需重新配对。
网页 Cookie 与设备令牌分别认证；原生来源不能携带 PC Cookie 代替设备令牌。

每次写入与 outbox 在同一 SQLite 事务内保存；请求失败保留操作。同一操作 ID 重传按服务器回执幂等。
服务器扫描当前账号记录识别现有 PC 修改与删除，按修订号分页下发。三方合并比较基线、本机与服务器：
不同字段自动合并，同一字段同时修改保留冲突副本，当前使用服务器值。
旧训练组没有元素 ID，因此组列表作为一个字段处理，避免错配重量/次数；可在手机设置导出双方副本或采用本机版本。
冲突副本另行导出 JSON，不伪装成旧 PC 不认识的健康 ZIP 表。

HTTPS 使用系统证书校验，拒绝重定向和明文 HTTP。原生网络限定方法、响应体和超时，
Key 不进入普通网页读回接口、日志或备份。WebView 禁止文件跨域访问与发布版调试，
CSP 禁止外来脚本、对象与内联脚本；JSON 校验器预编译，不需要 eval。
ZIP 限压缩 512 MiB、展开 2 GiB、10002 条目、清单 32 MiB；拒绝重复项、链接、额外路径、
损坏哈希和超限图片，正式数据仅在验证后事务切换。FileProvider 仅分享临时导出子目录。
这些是应用安全边界，不能防御已取得系统/root 权限的恶意软件；健康记录也应依赖设备锁屏与系统更新保护。

## 构建与验收边界

Node 24、Java 21、Android SDK 35，详见 [构建脚本](../scripts/android/README.md)。
`npm --prefix web run build` 输出 PC 静态页面；`build:mobile` 单独输出 mobile-dist 并同步原生工程，
两种构建不会互相覆盖。发布密钥保存在仓库外或被忽略的私有目录，后续升级必须使用同一签名。

本轮已在隔离数据下完成源码测试、PC/Android v1/v2 ZIP 往返（含合成照片）、原生 release 编译及签名校验。
Windows 原生目录/启动器、Android 8/11/14/15 真机、真实 AI 服务和真实公网部署仍需各自验收，
不能由 Linux 单元测试或 Gradle 编译推断通过。最新执行结果见 [验收](ACCEPTANCE.md)。
