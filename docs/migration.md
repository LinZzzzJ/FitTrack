# Windows → Ubuntu/WSL 移植开发清单

发布基线：v0.4.0、API 修订号 2；当前 `main` 源码为 API 修订号 3。整理日期：2026-10-23。本文区分当前源码检查与平台支持验收；Linux 完整运行和跨 OS 数据迁移仍未验收。

## 先区分三种目标

| 目标 | 当前可复用部分 | 仍需做的工作 |
|---|---|---|
| WSL 阅读/编辑，Windows 运行与发布 | 公开源码、知识库、现有 Windows 流程 | Linux 开发依赖重建；Windows 保留独立环境和回归 |
| 后端本身运行在 WSL/Linux | 前后端业务、SQLite 合约、AI 校验与数据格式 | 下面的平台适配、Linux 测试及浏览器验收 |
| 部署服务器提供网址 | 业务及 `server` 模式基础 | Linux 适配、HTTPS/代理、账户策略、运维与公网验收 |

仅切换编辑器不要求重写业务。服务在 Linux 完整运行时，不能把 Windows 接口直接隐藏后称为功能等价；应确定平台对应的操作方式并保持业务合约。

## 平台依赖与处理方向

以下“处理方向”均是**待实现方案**，不是当前代码行为：

| 模块/位置 | 已确认的当前实现 | 后续处理与验收 |
|---|---|---|
| `distribution.app_command` | 源码子进程路径固定 `.venv/Scripts/python[w].exe` | 按平台构造解释器命令；验证重启及根迁移后新实例就绪 |
| `desktop` / `native_dialog` | 原生 Windows IFileOpenDialog；Linux 无参数首次启动会要求 `--data-root` | Linux 先显式根目录；若提供桌面版，另实现目录选择及等效首次设置，不改变目录边界 |
| `RuntimeConfig.capabilities` | 按 `local/server` 返回能力，尚未完整按 OS 区分 | 能力与真实平台实现一致，前端不提供必失败入口；关闭能力须明确说明替代操作 |
| 打开目录 | `management_routes` 明确限制 Windows，最终调用 `os.startfile` | 明确 Linux 桌面/无桌面的行为，校验可打开范围及错误反馈 |
| 快捷方式/后台运行 | `.lnk`、PowerShell、`pythonw` 与 Windows 无控制台进程 | WSL 开发保持前台；Linux 本机服务另设计手动启停，不擅自增加开机自启 |
| 浏览器与冻结环境 | Windows HTTP 关联、Edge/Chrome 新窗口、`SetDllDirectoryW` | Windows 分支保留；Linux 区分桌面与无桌面，失败显示地址；不结束用户浏览器进程 |
| 文件锁 | Windows `msvcrt`、非 Windows `fcntl.flock` | 已有分支需验证重复启动、锁释放与异常退出，不能视为已验收 |
| 权限与链接防护 | Windows ACL/icacls；非 Windows chmod；拒绝符号链接/联接 | 验证实际文件系统权限、目录可写性、链接越界及原子替换，不弱化校验 |
| 路径/根迁移 | 相对工作区映射；部分迁移元数据记录旧绝对位置 | 清点 Windows 绝对路径、旧档登记及移走标志；测试中文/空格/大小写和复制失败回退 |
| 依赖与图像 | Argon2/Fernet/Pillow/SQLite/TLS 有原生或系统依赖 | Linux 重装锁定版本；验证四种图片、EXIF、TLS、密码和凭据加密 |
| 新增业务合约 | 当前源码含训练模板表、AI 文字餐食请求和纤维/糖/钠字段 | 健康 ZIP v2 携带训练模板；导入仍接受不含模板表的 v1 ZIP。验证旧餐食 JSON 中缺失营养键按未知值读取 |
| 便携构建与检查 | Windows EXE、`.ps1`、测试中的 `winreg`/`ctypes.windll` | Windows 打包保留；Linux 测试按真实职责划分，新增 Linux 作业后才声明支持 |

平台相关代码可从 [distribution](../src/fittrack/distribution.py)、[desktop](../src/fittrack/desktop.py)、[paths](../src/fittrack/paths.py)、[runtime](../src/fittrack/runtime.py) 与 [便携测试](../tests/test_portable.py) 开始检查。

## 推荐实施顺序与验收门槛

1. **建立独立克隆**：从 GitHub 的公开仓库开始，记录分支、提交和工具版本。不要复制开发机 `.venv`、`node_modules`、私人 `.git` 历史或真实数据。
2. **重建环境**：按 [environment](environment.md) 检查 Linux Python/Node/npm；所有试验缓存与数据放在明确的 `artifacts` 子目录，失败时不回退系统临时库。
3. **验证基础业务**：使用显式空根目录、独立端口、关闭桌面调用，验证账号、身体、手工餐食、训练、图表和模拟 AI。此时不承诺所有管理入口可用。
4. **实现平台边界**：先修正解释器命令和能力，再处理目录选择、文件浏览、后台/浏览器行为及重启迁移。保持现有 Windows 行为回归。
5. **验证数据合约**：用模拟数据进行备份、跨账号导入、个人迁移及整根迁移；核对所有权、数据库完整性、计数与图片哈希。
6. **完成双平台验收**：分别记录 Windows 和 Linux 的测试结果，按桌面/无桌面及 WSL 网络条件验收界面。再更新 CI 矩阵、支持声明和发布形式。

如果需要改 API、请求模型或备份格式，应先列出兼容策略；普通 OS 适配不应顺带修改热量公式、周资格、统计锚点和 AI 自动调用策略。

## 源码迁移与运行数据迁移分别处理

Git 迁移的是受版本管理的源码与文档，不带账号库、Key、照片和运行状态。两台电脑分别克隆后，`commit` 保存本机版本，`push/pull` 同步已提交源码；旧 Release 不会随 `main` 自动变化。

数据迁移有两种不同需求：

| 方式 | 包含 | 不包含/限制 |
|---|---|---|
| 个人健康 ZIP 导入 | v2 包含记录、任务、标签快照、照片及个人训练模板；导入后归入目标账号。仍接受不含模板表的 v1 归档 | 不含登录密码、API Key 和主密钥；需要目标账号重新配置凭据 |
| 停服后的整个根目录复制 | 控制库、账号、个人工作区、凭据密文及主密钥等 | 不应直接信任旧进程状态；路径、权限、旧档标志及跨 OS 启动需单独核验 |

跨 Windows/Linux 的这两条路径都**尚未完成实测**。优先用模拟数据验证标准健康 ZIP，再测试完整根副本；不能将格式可读推断成迁移已成功。

验证完整根迁移时，先正常停服并保留源目录，确认 SQLite 连接关闭；不要只复制运行中的 `.sqlite3` 而遗漏 WAL。不要让 Windows 和 Linux 同时使用同一根目录/数据库，尤其不能将各自的实例锁机制当作跨 OS 协调保证。[SQLite WAL 说明](https://www.sqlite.org/wal.html)

主密钥不是登录密码，必须与密文匹配。主密钥丢失时不可覆盖旧凭据来“修复”；个人健康数据仍可访问，凭据需恢复或重新配置。验证迁移成功前不删除源目录，也不迁移正式资料做验收。

## 测试矩阵

| 类别 | 双平台应验证的场景 |
|---|---|
| 写入边界 | 显式根目录、临时目录不可写、不回退、中文/空格、大小写与链接越界 |
| 生命周期 | 重复启动、端口冲突、正常退出、任务中退出、服务身份、重启及根迁移就绪 |
| 账号/凭据 | 两账号隔离、会话退出、记住/不记住、主密钥权限与丢失 |
| 饮食 | 历史周、标签换算、文字/照片 AI 草稿、营养未知值、重复确认、删除分析后餐食/图片不变 |
| 训练/建议 | 模板账号隔离与当天副本、CSV/JSON 导入、二维码扫码、实际训练日历、羽毛球及 AI 过期检测 |
| 图片 | JPEG/PNG/WebP/GIF、原图字节、EXIF、等比缩小、缓存与归属 |
| 数据管理 | 备份恢复、跨账号导入、旧档保留、失败回退、图像哈希 |
| 平台与 UI | 能力与实际一致、浏览器/无桌面行为、桌面与窄窗口、Windows EXE 回归 |

v0.4.0 Windows 发行有 129 项后端测试及成品验收。当前 `main` 源码在 Linux Python 3.14.4 环境排除 `test_portable.py` 后 124 项通过、2 项跳过；完整 Linux 测试中的 Windows API 失败不计为 Linux 功能回归。Linux 启动器、管理操作、浏览器全流程、整根迁移和新功能 Windows 成品仍未验收。详细范围见 [ACCEPTANCE](ACCEPTANCE.md) 与 [open_questions](open_questions.md)。
